# Feed ranking: offline evaluation

Generated by `tools/ranking/train_eval.py`. Data is **synthetic** (see
[ranking.md](ranking.md) for why and for what that does and does not show).

- Posts: 100,000. Embedding: LSA, 64 dimensions, vocabulary 281 terms, 60% of TF-IDF variance kept.
- Train: days 4-24, 1,264,260 impressions, 29,400 likes.
- **Held-out test: days 25-29, 300,300 impressions, 6,789 likes**, 5,471 (user, day) ranking lists with at least one like.
- Task: re-rank each user's daily impressions; relevance = liked. Metric: mean nDCG@10.

| Method | nDCG@10 | vs. chronological |
|---|---|---|
| Random | 0.2365 | -34.3% |
| Chronological (newest first) | 0.3598 | +0.0% |
| Popularity (most liked) | 0.3009 | -16.4% |
| Embedding similarity only | 0.3440 | -4.4% |
| Ranker (all features) | 0.4102 | +14.0% |

**Reference ceiling** (analysis only): ranking by the generator's true like-probability scores 0.5212. The ranker closes **31%** of the gap between chronological and this ceiling. The ceiling reads hidden variables no real system has.

## Experiment: impression logging

Adding a smoothed like-rate feature, likes / impressions, gives nDCG@10 **0.4121** (+0.5% over the deployed ranker). It needs impressions to be logged online, which the API does not do yet, so it is not deployed. The gain is small on this data, so impression logging is not a priority for ranking quality alone (it is still the standard source of negative training examples).
